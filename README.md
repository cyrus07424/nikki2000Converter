# 日記帳2000 Rust 版

ぽてと様のオリジナル版「日記帳2000」([公式サイト](https://www.poteto-house.com/poteto/soft-old.html#nikki)) の `.DAY` ファイルを読み書きし、日記を一覧・編集・検索し、CSVへ出力する Windows デスクトップアプリです。

## 使い方

1. ビルド済みの `nikki2000-converter.exe` を用意します（[GitHub Releases](https://github.com/cyrus07424/nikki2000Converter/releases) からダウンロードできます）。
2. 実行ファイルをオリジナル版 `nikki.exe` がインストールされているフォルダーに置きます。
3. `nikki2000-converter.exe` を起動します。同じフォルダーの `DATA` を自動で読み込みます。

インストーラーは不要です。オリジナル版の `nikki.exe` やデータを上書きせず、日記ファイルはアプリ内で「保存」を押したときだけ変更します。`DATA` が別の場所にある場合は、アプリ内の「フォルダーを選択」から指定できます。

ソースからビルドする場合は、Rust stable と Windows MSVC ビルドツールがある環境でリポジトリのルートから実行します。

```powershell
cargo build --release
```

実行ファイルは `target\release\nikki2000-converter.exe` に生成されます。

## 主な機能

- 月ごとの `.DAY` ファイルを読み込み、日付順に一覧表示
- 日記本文、保存された天気・気分コード、記念日フラグの閲覧と編集
- 本文検索、新しい日付の作成
- 読み込んだ日記を UTF-8 BOM 付き CSV としてエクスポート
- 既存の `.DAY` ファイルを互換形式で保存

天気はオリジナル版と同じ 28 通り、気分は同じ 4 通りから選択できます。天気は静的解析で確認した図柄順を「太陽」「雲」「傘」「雪だるま」と「／」「→」の組み合わせで説明し、気分は「笑顔」「ふつう」「悲しい」「怒り」と表示します。これらはアイコンに基づく説明語で、オリジナル版の正式な表示文言ではありません。「／」「→」を「時々」「のち」などの気象用語に置き換えてはいません。保存コードも併記し、未対応のコードは変更しない限りそのまま保持します。

CSV の列は `date`, `weather_code`, `mood_code`, `is_anniversary`, `entry` です。天気・気分のコードは `.DAY` に保存された数値をそのまま出力します。

Windows ではシステムの日本語フォントを読み込みます。完全に空の新規日記はオリジナル版の保存動作に合わせて追加しません。

## `.DAY` 互換性

実装はオリジナル版 `nikki.exe` の静的解析と、ユーザーが合成データと確認したファイルの構造照合に基づきます。ファイルは `N20` シグネチャ、レコード数、本文長、XOR `0x12` で変換された本文から成り、本文には日ごとのレコードが格納されます。日本語本文は Shift-JIS / CP932 として扱い、未編集のレコードは元の本文バイト列を保持します。

解析根拠、確認済みの構造、適用範囲および未解明点は [`FORMAT_ANALYSIS.md`](FORMAT_ANALYSIS.md) に記載しています。パスワード機能はオリジナル版の設定・起動制御に属し、`.DAY` 本文の暗号化には使われていません。XOR は難読化であり、機密保護ではありません。

このアプリは正常な `.DAY` 構造を厳密に検証し、破損・未対応のファイルは内容を表示せずエラーとして報告します。オリジナル版 `N12` 形式の変換仕様は未解析のため、対応していません。参考用の Python コンバーターは [`old/decode_all.py`](old/decode_all.py) に保管しています。そこに記載された 13 バイトヘッダーやフラグ解釈はオリジナル版実行ファイルと一致しないため、本アプリの仕様根拠にはしていません。

## Dependabot と自動マージ

Dependabot は Cargo と GitHub Actions の依存関係を毎週更新します。Dependabot の pull request には `dependencies` ラベルが付き、Windows 向け pull request 検証が成功した現在のコミットに限り `automerge` ラベルが付きます。新しいコミットが push されると自動マージラベルを外し、最新コミットの検証が成功するまで再付与しません。

自動マージの実行には、GitHub 上で Mergery アプリをリポジトリへインストールし、必要なマージ方式と保護ルールを設定する必要があります。このリポジトリのワークフローはアプリの導入やブランチ保護設定を変更しません。マージ条件として `Pull request validation / validate` を必須チェックにすることを推奨します。

## 自動ビルドとリリース

ブランチへ push するたびに GitHub Actions が整形チェック・テストを実行し、Windows x64 の Release 実行ファイルをビルドして GitHub Release に prerelease として添付します。成果物はインストーラー不要の `nikki2000-converter.exe` です。各ワークフロー実行は実行IDと再試行番号から一意なタグを作成し、既存タグやReleaseを上書きしません。ワークフローにはリポジトリの `contents: write` 権限が必要です。

## テスト

```powershell
cargo test
cargo build --release
```

テストはコード内で生成する合成フィクスチャのみを使用し、個人の日記内容を含みません。
