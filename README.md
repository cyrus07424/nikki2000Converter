# 日記帳2000 Rust 版

日記帳2000の `.DAY` ファイルを読み書きし、日記を一覧・編集・検索し、CSVへ出力する Windows デスクトップアプリです。インストーラーは不要で、ビルドした実行ファイルから直接起動できます。

## 起動とビルド

Rust stable と Windows MSVC ビルドツールがある環境で、リポジトリのルートから実行します。

```powershell
cargo build --release
```

実行ファイルは `target\release\nikki2000-converter.exe` です。実行ファイルの隣に `DATA` フォルダーがあれば自動で読み込みます。別の保存場所はアプリ内の「フォルダーを選択」から指定できます。選択したファイルは、明示的に「保存」を押すまで変更しません。

## 主な機能

- 月ごとの `.DAY` ファイルを読み込み、日付順に一覧表示
- 日記本文、保存された天気・気分コード、記念日フラグの閲覧と編集
- 本文検索、新しい日付の作成
- 読み込んだ日記を UTF-8 BOM 付き CSV としてエクスポート
- 既存の `.DAY` ファイルを互換形式で保存

CSV の列は `date`, `weather_code`, `mood_code`, `is_anniversary`, `entry` です。天気・気分コードの数値範囲は旧アプリから確認できましたが、各数値と画面上の日本語ラベル／アイコンとの対応は未確定です。誤った意味付けを避けるため、このアプリでは数値コードをそのまま表示・出力します。

Windows ではシステムの日本語フォントを読み込みます。完全に空の新規日記は旧アプリの保存動作に合わせて追加しません。

## `.DAY` 互換性

実装は旧 `nikki.exe` の静的解析と、ユーザーが合成データと確認したファイルの構造照合に基づきます。ファイルは `N20` シグネチャ、レコード数、本文長、XOR `0x12` で変換された本文から成り、本文には日ごとのレコードが格納されます。日本語本文は Shift-JIS / CP932 として扱い、未編集のレコードは元の本文バイト列を保持します。

解析根拠、確認済みの構造、適用範囲および未解明点は [`FORMAT_ANALYSIS.md`](FORMAT_ANALYSIS.md) に記載しています。パスワード機能は旧アプリの設定・起動制御に属し、`.DAY` 本文の暗号化には使われていません。XOR は難読化であり、機密保護ではありません。

このアプリは正常な `.DAY` 構造を厳密に検証し、破損・未対応のファイルは内容を表示せずエラーとして報告します。旧 `N12` 形式の変換仕様は未解析のため、対応していません。旧Pythonコンバーターは参考用として [`old/decode_all.py`](old/decode_all.py) に保管しています。そこに記載された 13 バイトヘッダーやフラグ解釈は旧実行ファイルと一致しないため、本アプリの仕様根拠にはしていません。

## 自動ビルドとリリース

ブランチへ push するたびに GitHub Actions が整形チェック・テストを実行し、Windows x64 の Release 実行ファイルをビルドして GitHub Release に prerelease として添付します。成果物はインストーラー不要の `nikki2000-converter.exe` です。各ワークフロー実行は実行IDと再試行番号から一意なタグを作成し、既存タグやReleaseを上書きしません。ワークフローにはリポジトリの `contents: write` 権限が必要です。

## テスト

```powershell
cargo test
cargo build --release
```

テストはコード内で生成する合成フィクスチャのみを使用し、個人の日記内容を含みません。
